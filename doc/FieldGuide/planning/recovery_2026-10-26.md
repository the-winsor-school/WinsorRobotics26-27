## Changes to the handoff method

PROCESS now requires a backlog entry before scripted work and a durable run
record with process identity, goal, command, outputs, and logs.  Successful
execution gets the status `needs-review`;  acceptance is recorded separately
in BACKLOG.  Interrupted runs are reconciled with their actual output before
rerunning.  Drafts and notes are saved entry by entry.

## Source corrections to carry into drafting

The local references are useful, but the label "verified" needs a boundary.
The audit had already found inconsistent gear products and an unsupported
40 W HD Hex claim.  On 2026-10-26, the linked REV documentation confirms:

- [HD Hex Motor](https://docs.revrobotics.com/duo-build/motion/motors/hd-hex-motor):
  bare motor maximum output power is 15 W;  the local 40 W claim is wrong.
- [Core Hex Motor](https://docs.revrobotics.com/duo-build/motion/motors/core-hex-motor):
  internal reduction is 72:1;  288 encoder counts describe an output revolution.
  The local reference's 20:1 and physical output-shaft encoder description are wrong.
- [Cartridge Details](https://docs.revrobotics.com/rev-crossover-products/ultraplanetary/cartridge-details):
  use the fractions 84/29, 76/21, and 68/13 when calculating compounded ratios.
- [UltraPlanetary Load Ratings](https://docs.revrobotics.com/rev-crossover-products/ultraplanetary/load-ratings):
  40 N-m is described as a failure threshold, with shock and cantilevered loads
  reducing what the system withstands.  It is unsuitable as a working target.

Chapter 17 notes will record the corrected examples and the consequences for
motor selection.  Keep robot code unchanged while correcting the book.
